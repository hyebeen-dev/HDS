## 배경

"완성된 화면 없이 컴포넌트만 만들다 보니 무엇을 얼마나 챙겨야 할지 감이 안 잡힌다"는 고민에서 출발, 현재 컴포넌트 세트로 실제 화면 1개를 조립해 빠진 케이스를 발견하는 테스트를 진행했다. 목적은 완성도가 아니라 **간극 발견**.

## 실행 내용

App Bar(status=search) + 필터 Chip 행(전체/로켓내일/로켓프레쉬/로켓직구) + Item Card 2열×3행 그리드를 실제 컴포넌트 인스턴스로 조립했다. Grid 파운데이션 스펙(콘텐츠 폭 328px = 160px 카드×2 + 8px 거터)과 정확히 일치하게 배치됨을 확인했다.

## 조립하면서 발견한 간극

1. **카테고리 목록에 맞는 App Bar가 없음** — 지금 쓸 수 있는 건 "검색창이 열린" search 타입뿐이라, "카테고리명 + 뒤로가기 + 장바구니"로 구성되는 일반적인 목록 화면 상단바를 대체할 수 없었다. Tier 1 체크리스트의 **App Bar Sticky**가 왜 필요한지 실제로 확인된 사례.
2. **광고 상품 구분 표기가 없음** — PRD P1(강조 위계)이 명시적으로 지적한 "광고 상품과 일반 상품이 시각적으로 유사하다" 문제가 이 화면에서 그대로 재현된다. **Ad Container / Promotion Badge**(Tier 2)가 없으면 이 문제를 화면에서 풀 수가 없다.
3. **결과 수·카테고리명을 보여주는 헤더가 없음** — "생활용품 486개" 같은 목록 상단 정보 영역이 없어 화면이 바로 카드로 시작한다. **Section Header**(Tier 1)의 필요성이 확인됨.
4. **정렬(Sort) UI 부재** — Chip에 Dropdown=True variant 자체는 있지만, 실제 라벨("전체")만 있고 "정렬"이라는 텍스트를 새로 타이핑할 수 없어(폰트 제약) 정렬 버튼처럼 보이지 않는다. 컴포넌트 부재라기보다 **콘텐츠(라벨 텍스트) 다양성 부족** 문제.
5. **6개 카드가 전부 동일 상품** — Pretendard 폰트를 이 환경에서 로드할 수 없어 상품명·가격 등을 새로 타이핑하지 못해 같은 인스턴스를 반복 사용했다. 구조 검증에는 문제없지만, 실제 "여러 상품 비교" 시나리오(PRD §7)를 시각적으로 보여주진 못한다.
6. **목록 하단 처리 없음** — 무한 스크롤 로딩/Skeleton/더보기 버튼 등 목록 끝 처리가 전혀 없다. Tier 3의 **Skeleton**과 연결되는 지점.

## 검증

- 스크린샷으로 App Bar/Chip 행/Item Card 그리드가 겹침 없이, Grid 스펙과 일치하는 폭으로 배치됨을 확인

## 다음 단계 후보

1. Section Header, App Bar Sticky를 먼저 만들면 이번에 발견된 간극 1·3이 바로 해결됨
2. Ad Container/Promotion Badge 제작 시 이 화면에 실제로 꽂아서 P1 문제가 실제로 해결되는지 재검증
3. Pretendard 설치 이슈가 해결되면 6개 카드에 서로 다른 상품 데이터를 넣어 재검증
