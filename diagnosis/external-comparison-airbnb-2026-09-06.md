# 외부 디자인 시스템(Airbnb) 비교 분석

**작업일** 2026-09-06
**비교 대상** `design-references/airbnb-design.md`(외부 기업 디자인 시스템 분석 문서, alpha 버전)
**대상 우리 문서** `design-system/design.md` v0.33
**작업 성격** 100% 문서 대조. Figma·design.md 어떤 것도 수정하지 않음. 외부 문서는 "비교·평가 기준"으로만 쓰고, 색상·폰트·spacing·radius·component 구조 등 실제 값은 어떤 것도 우리 쪽에 이식하지 않았다.
**원칙**: Figma·design.md가 Source of Truth이고 외부 문서는 참고 자료일 뿐이다. "외부 회사에는 있으니 우리도 추가해야 한다"는 판단은 하지 않고, 우리 프로젝트에서 실제로 필요한지를 기준으로 골랐다.

---

## 1. 종합 판정

현재 `design.md`의 완성도는 **높다**. 15개 컴포넌트 전부 Do/Don't·Variant·Content 규칙, Figma node ID, 화면 조합 패턴(`§6`)까지 갖췄고, 실제 화면 3건(장바구니/영화상세/활동대시보드)으로 검증까지 거쳤다. 다만 문서 스스로도 인정하듯(v0.33 변경이력) "특정 커머스 UI를 설명하는 수준(A)"에 더 가깝고, 범용 컴포넌트(Form/Chart/Empty State)는 약하다.

Airbnb 문서와 대조한 결과, 우리 문서가 구조적으로 못하다기보다(오히려 컴포넌트 1개당 문서 밀도는 우리가 더 높다) **커머스 화면 바깥의 기본기(입력 필드, 접근성, 모션 타이밍)에 공백이 있다**는 것이 이번 비교의 핵심 발견이다.

---

## 2. [우리 문서에 실제로 부족한 규칙]

프로젝트 성격과 무관하게, 우리 프로젝트 자체를 위해서도 채워야 하는 항목.

- **Text Input / Form Field 컴포넌트가 아예 없음** — Badge~Radio/Checkbox까지 15개 체크리스트 어디에도 "입력창"이 없다. Airbnb는 `text-input`(default/focus/error) 상태를 명시하는데, 우리는 배송지 변경·검색·쿠폰코드·리뷰 작성처럼 텍스트 입력이 실제로 필요할 가능성이 높은 화면이 있는데도 규칙이 전무하다. AI가 만들면 완전히 즉흥적으로 만들 수밖에 없다.
- **터치 타겟 최소 크기 기준 부재** — Airbnb는 "Touch Targets" 섹션에서 48×48/32×32 같은 실제 탭 영역을 명시한다. 우리는 `Icon Button Small`(32px), `Chip`, `Rocket Badge` 등 작은 인터랙티브 요소가 많은데 최소 히트 영역 기준이 어디에도 없다.
- **폰트 대체(fallback) 스택 미문서화** — `status.md`에 이미 "Pretendard를 이 실행환경에서 로드 못해 11개 스타일 생성 대기" 이슈가 실제로 있었는데도, `design.md §1.2 Typography`에는 Pretendard 미가용 시 대체 폰트 규칙이 없다.
- **인터랙션 타이밍/모션 기준 없음** — Toast 노출시간(3초)만 예외적으로 문서화돼 있고, Dialog/Bottom Sheet의 열림·닫힘 트랜지션, 버튼 Pressed 상태 전환 등 나머지 전부에 timing/easing 규칙이 없다.
- **색상 대비(접근성) 검증 기준 부재** — `Text/Description`(#7b818e) on `Background`(#f4f6f6) 같은 조합이 AA를 만족하는지 판단할 기준이 문서에 없다.

## 3. [우리 문서에는 없지만 현재 프로젝트에서는 필요하지 않은 규칙]

Airbnb에는 있지만 우리 프로젝트 범위상 지금 만들 이유가 없는 것들.

- **Responsive 브레이크포인트 체계**(Mobile/Tablet/Desktop/Wide) — `§1.4 Grid`에 "PRD 범위가 Mobile-first라 멀티 브레이크포인트를 도입하지 않았다"고 이미 명시적으로 결정돼 있다.
- **Hover state 정의** — 모바일 터치 전용 앱이라 hover 자체가 존재하지 않는 상호작용이다.
- **서브 브랜드 팔레트**(Luxe/Plus 같은 개념) — 우리 프로젝트에 서브 브랜드가 없다.
- **Date Picker 컴포넌트** — 현재 화면 구성에 배송일자 선택 같은 기능이 없다.
- **Desktop 전용 Top Nav/Footer 구조** — Bottom Navigation 기반 모바일 앱 구조와 무관하다.

## 4. [외부 문서의 스타일/철학이라 우리 프로젝트에 적용하면 안 되는 것]

참고만 하고 절대 이식하면 안 되는 부분 — 우리 문서에는 이미 반대되는 원칙이 결정돼 있다.

- Rausch(#ff385c) 단일 브랜드 컬러 + 화이트/포토그래피 중심 미학 — 우리는 파랑 Primary + "가격 강조는 Error/Gray"라는 이미 확정된 색 의미 체계(`§1.1`, `§4` 원칙2)가 있다.
- "거의 모든 곳이 둥글다"는 pill 우선 철학 — 우리는 "작고 인터랙티브한 요소일수록 둥글고, 카드/Action Bar는 의도적으로 각지다"는 반대 원칙(`§1.5`, `§4` 원칙3)이 이미 확정돼 있다.
- 64px 초대형 rating 타이포 같은 "브랜드 임팩트 포인트" 연출 — 우리는 "Commerce 숫자는 크기보다 weight로 위계를 나눈다"(`§4` 원칙5)는 반대 철학을 채택 중이다.
- 그림자 기반 1-tier elevation(hover-float shadow) — 우리는 "그림자 대신 선"(`§1.6`, `§4` 원칙4) 원칙이 이미 실측 확정돼 있다.
- 64px 섹션 여백 같은 에디토리얼 넓은 여백 철학 — 우리는 16px/8px가 지배적인 리듬이라고 이미 실측돼 있다(`§1.3`).

## 5. [우리 문서에 추가하면 AI가 UI를 만드는 데 도움이 될 만한 "문서화 방식"]

내용이 아니라 **구조**만 차용할 만한 것.

- **"Known Gaps" 같은 명시적 섹션을 Foundation/Interaction 레벨에도 별도로**: 지금 `§5`는 컴포넌트 백로그 위주라, "터치 타겟 미정의", "인터랙션 타이밍 미정의", "색 대비 기준 미정의"처럼 Foundation 자체의 공백을 한눈에 보여주는 목록이 따로 없다. `§0` 원칙4(모호함 표면화)와 정확히 같은 정신이니 확장하기 자연스럽다.
- **"Note on Font Substitutes" 패턴**: Pretendard 미가용 환경(코드젠, 웹 등) 대응 스택을 `§1.2` 하위에 서브섹션으로 명문화 — 이미 실제로 겪은 문제라 바로 실익이 있다.
- **최상단 "한눈에 보기" 요약**: `design-language.md`에 이미 있는 시각 스타일 관찰 내용을 design.md 맨 위에 5~8줄로 요약해두면, design-language.md를 따로 열지 않아도 AI가 전체 gestalt를 빠르게 파악할 수 있다.

## 6. 결론 요약

**A. 현재 완성도**: 높음. Figma 실측 기반, 15개 컴포넌트 전부 규칙화, 화면 조합 패턴·실화면 검증까지 완료. 단 커머스 도메인 특화 수준(A)이고 범용 기본기는 약함.

**B. 외부 대비 부족한 문서화 영역**: Form/Input, 접근성(터치타겟·색대비), 인터랙션 타이밍/모션, 폰트 fallback.

**C. 실제 UI 품질에 영향을 줄 정도로 반드시 보완 필요**
1. Text Input/Form Field 컴포넌트 — 체크아웃·검색·리뷰작성 등에서 실사용 가능성이 높은데도 완전 공백.
2. 터치 타겟 최소 크기 기준 — 작은 인터랙티브 요소가 많은 커머스 리스트/필터 UI 특성상 실질적 사용성에 영향.
3. 모달/시트 인터랙션 타이밍 — Dialog·Bottom Sheet 열림/닫힘 애니메이션 기준 부재.

**D. 굳이 추가하지 않아도 되는 항목**: Responsive 브레이크포인트 체계, Hover state, 서브 브랜드 팔레트, Date Picker, Desktop 전용 Nav/Footer.

**E. 현재 design.md만으로 새 화면을 만들 때 Claude가 가장 많이 추측하게 될 부분**
- 사용자 입력 필드(폼) 스타일 전체
- 작은 탭 요소들의 히트 영역 크기
- 모달/시트의 열림-닫힘 애니메이션·트랜지션 timing
- 텍스트/배경 색상 대비(가독성) 기준
- (문서가 이미 자각한 부분) Chart/Stat 카드, Empty State, Skeleton, 비인터랙티브 태그 컴포넌트 — 커머스 밖 도메인 화면 생성 시
