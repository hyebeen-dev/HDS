# UI 검증 — "영화 상세 정보" 화면 (도메인 일반화 검증)

**목적**: design.md가 특정 커머스 화면을 넘어 새로운 도메인의 UI에도 일관된 디자인 언어를 적용할 수 있는지 검증. 예쁜 영화 화면을 만드는 게 목표가 아니라, design.md에 없는 내용을 임의로 지어내 그럴듯하게 완성하기보다 어디서 판단이 어려웠는지를 명확히 드러내는 것이 목표였다.

**Figma**: https://www.figma.com/design/y8OcE4JLKi7ADIPCVFJQej/HDS_2609?node-id=6767-474 ("Ⓝ Note" 페이지)

**조건**: 기존 상품목록/카테고리/상품상세/장바구니 화면의 레이아웃·콘텐츠 구조를 복제하거나 다른 콘텐츠로 치환하지 않음. design.md → Foundation/Variables → Components → 기존 화면 순으로 우선 판단하되, 커머스 전용 컴포넌트를 억지로 끌어쓰지 않음.

## 1. 재현된 디자인 언어
- `## 6. Screen Composition Patterns`의 "패턴 2"(헤더 뒤 divider 없이 콘텐츠 시작, 1px=섹션 내부/8px=섹션 간 구분)가 커머스가 아닌 화면에도 억지 없이 그대로 들어맞았다.
- 색상은 `Text/Primary`/`Text/Description`/`Background/Divider`만 사용(새 색 0개), Typography는 `heading/medium`/`body/medium`/`body/small-bold`/`label/xsmall-medium`(새 스타일 0개), Radius는 `full`(태그·아바타)/`none`(포스터), Spacing은 16/8/40 — 전부 기존 값.
- §4 원칙 11(자유 텍스트는 자동 줄바꿈)이 영화 설명 문단에도 그대로 적용됨.

## 2. 판단이 필요했던 부분
- 포스터 비율(2:3 세로) — design.md에 이미지 비율 규칙 자체가 없어(Foundation "Image" 항목 자체가 미착수) 임의 결정.
- App Bar를 아이콘 전용(제목 텍스트 숨김)으로 구성 — 기존 상품 상세 화면의 관행을 근거로 판단(문서에 명문화된 규칙은 없음).
- 장르/관련 태그 표시 방식 — `Chip`은 인터랙티브 전제라 안 맞고 `Label`은 Type 값이 커머스 전용이라 raw pill로 대체.
- `Rating Display`의 "리뷰 수" 문구를 "평가 인원수"로 재해석 — 형식은 유지하되 어휘만 도메인에 맞춤.
- 캐스트(인물) 표현 방식 — 기존 리뷰 작성자 아바타 패턴을 일반화(명시 규칙 없음).
- `Action Bar` 2-Button의 "찜하기"(Secondary)+"예매하기"(Primary) 배치 — 기존 2-Button 배치 관례(짝지어진 차선책)를 그대로 적용.

## 3. 재사용한 컴포넌트
`App Bar`(Type=Title, 아이콘만), `Section Header`(Show Action=false)×4, `Rating Display`(Review=Filled), `Action Bar`(Layout=2 Button) — 4개, 전부 텍스트 override만 하고 새 Variant는 추가하지 않음.

## 4. 새롭게 필요한 UI
- 태그 pill(장르/관련 태그) — `Label`/`Chip` 둘 다 안 맞아 raw 구성.
- 캐스트 아이템(원형 아바타+이름+역할) — 대응 컴포넌트가 아예 없음.
- 라벨-값 정보 행(감독, 추가 정보) — 컴포넌트는 없지만 상품 상세 화면의 "총수량/유통기한" raw 패턴을 그대로 재사용(완전한 신규 발명은 아님).
- 포스터 이미지 프레임 — 컴포넌트 아님, Foundation 토큰(Radius `none`, `Gray/200`)만으로 구성.

## 5. design.md의 한계
- §2 Component의 절반 이상(Item Card 계열, Price Block, Spec Row, Rocket Badge, Cart 전용 4종, Order Deadline, Status Badge)이 태생적으로 커머스 전용이라 이번 화면에서 단 하나도 못 씀.
- **`Label`과 `Chip` 둘 다 "비인터랙티브 순수 표시용 태그"라는 흔한 UI 니즈를 커버하지 못함** — `Label`은 Type 값이 커머스 전용이라 확장해도 어색하고, `Chip`은 인터랙티브 전제라 억지로 쓰면 안 됨. 구조적 공백.
- "사람/프로필" 표현 패턴이 공식 컴포넌트로 존재하지 않음 — 리뷰 작성자 아바타가 유일한 단서인데 그마저 raw 구현이라 재사용 가능한 형태가 아님.
- 이미지 비율/플레이스홀더 규칙이 아예 없음(기존에도 알려진 공백).
- `## 6. Screen Composition Patterns`는 커머스 화면 5개에서만 추출돼 있었는데, "포스터+정보"형 상세 화면 같은 새로운 아키텍처에도 패턴 2가 억지 없이 들어맞았다는 것 자체가 이번에 처음 검증된 긍정적 신호.

## 6. 종합 평가

🟡 **기본적인 디자인 언어는 적용 가능하지만 일부 규칙 보완 필요**

Foundation 토큰과 `App Bar`/`Section Header`/`Rating Display`/`Action Bar`처럼 "형태가 범용적인" 컴포넌트는 커머스를 벗어나도 그대로 통했다. 하지만 §2 Component의 상당수가 커머스 전용이라 재사용 폭이 좁았고, "태그 표시"·"인물 표현"이라는 흔한 UI 니즈에 대응하는 컴포넌트가 없다는 구조적 공백이 드러났다. Foundation·화면구성 원칙은 도메인 무관하게 이식 가능하지만, Component 레이어는 아직 커머스 화면을 설명하는 수준에 가깝다.

## 피드백 반영 (2026-09-05)

사용자가 완성된 화면(`6767:474`)을 검토하고 4개 피드백을 줬다. 아래는 피드백 원문 + 진단 + 실제 반영 내용이다.

### 1. App Bar 영역: 페이지 타이틀을 작성하지 않으면 유저가 어느 페이지를 보고 있는지 직관적으로 파악하기 어려움
**진단**: 상품 상세 화면의 App Bar가 아이콘만 쓰는 걸 관찰하고 그 관행을 그대로 옮겨 "category" 텍스트를 숨겼는데, 이는 App Bar 자신의 기존 문서화된 Content 규칙("Title 제목은 장바구니처럼 2~4자 명사형")과 정면으로 배치되는 선택이었다. 참고 화면 1개의 예외적 사례를 컴포넌트 자체의 기본 목적보다 우선시한 판단 오류.
**반영**: App Bar 타이틀 텍스트를 "영화 상세"로 복원(Figma 실행).

### 2. 썸네일 영역에 Thumbnail 컴포넌트를 사용하지 않은 이유가 무엇인지?
**진단**: `Thumbnail`(§2.14)은 전 사이즈(xsmall 36×36 ~ Xlarge 360×360)가 전부 정사각형이고, 사용가이드에도 "정사각형 이미지" 전용으로 명시돼 있다. 영화 포스터는 2:3 세로 비율이라 애초에 어떤 사이즈로도 대응이 안 돼 의도적으로 쓰지 않았다.
**반영**: Figma 변경 없음(질문에 대한 답변). design.md §2.14에 "세로형 비율에는 못 쓴다"는 Don't 항목을 신규 추가해 향후 같은 질문이 안 나오게 함.

### 3. "잊혀진 서점에서 시작되는 세 가족의 재회" — 폰트가 유독 눈에 띔. 한줄 소개는 영화 설명 영역에 포함되는 게 자연스러울 것 같음
**진단**: 정보 블록 맨 아래 단독 bold 문장으로 배치했던 게 문제 — 구조적으로 "영화 설명" 섹션에 속하는 내용이었다.
**반영**: 정보 블록에서 제거하고, "영화 설명" 섹션의 설명 문단 바로 위에 bold 첫 줄로 이동(Figma 실행).

### 4. cast-item — 배우명, 배역명 사이 간격이 너무 넓음. 6px인데, spacing 규칙이 적용되지 않은 것 같음
**진단**: 실측 결과 `itemSpacing`은 정확히 6px로 적용돼 있었다(토큰 자체는 문제 없었음). 원인은 텍스트 노드의 150% 줄간격이 이미 박스 안에 여백을 포함하고 있어서(14px Bold 텍스트의 박스 높이가 21px = 14×1.5), 6px의 `itemSpacing`이 그 위에 더해져 체감 여백이 훨씬 커 보인 것.
**반영**: `itemSpacing`을 6→2로 축소(기존 Spacing 예외 토큰 그대로 사용, 새 값 발명 아님, Figma 실행).

### 이번 피드백에서 얻은 인사이트
1. **참고 화면의 예외 사례 vs 컴포넌트 고유 목적의 충돌** — 새 화면을 만들 때 특정 참고 화면 하나의 관찰이 컴포넌트 자체의 문서화된 목적과 배치될 수 있고, 이럴 땐 컴포넌트 고유 목적이 우선이다.
2. **Thumbnail의 정사각형 전용 한계**가 실제 시도로 재확인됐다 — "이미지 비율 규칙 미정의"라는 기존 공백의 구체적 사례.
3. **spacing 토큰과 텍스트 줄간격의 중첩 효과** — 짧은 텍스트를 세로로 촘촘히 쌓을 때는 nominal spacing 값이 시각적으로 부풀려 보인다. 토큰이 틀린 게 아니라, 토큰 적용 결과를 텍스트 인접 상황에서는 반드시 스크린샷으로 재확인해야 한다는 교훈.
4. **콘텐츠 배치(IA) 판단은 토큰/컴포넌트 문제가 아니다** — 한줄 소개의 위치 문제는 Foundation/Component 어느 규칙 위반도 아니었고, 순수하게 "이 정보가 어느 섹션에 속하는가"라는 콘텐츠 구조 판단이었다.
