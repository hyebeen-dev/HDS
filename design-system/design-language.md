# Design Language

실제 UI에서 반복되는 시각 스타일을 관찰해 정리한 문서입니다.

---

- 최초 작성일: 2026-09-02
- 대상 Figma 파일: Design System_0901
- 조사 대상
  - Foundation: Color, Typography, Grid, Spacing
  - 컴포넌트: Button, Item Card 4종, Price Block, Spec Row, Chip, Cart Item, Action Bar, Review Card, App Bar, Section Header
  - 실제 화면: 상품목록 그리드, 상품목록 리스트, 장바구니, 상품 상세페이지

## 1. 전체 UI 관찰

Foundation, 컴포넌트, 실제 화면에서 공통으로 반복되는 패턴은 네 가지입니다.

- 정보가 원색 강조 요소와 무채색 본문으로 분리되어 있습니다. 할인율 배지, 로켓 배지, CTA 버튼처럼 색이 들어간 요소는 모두 둥근 형태의 독립된 단위입니다. 상품명, 배송 설명, 옵션 같은 정보 텍스트에는 무채색만 씁니다.
- 강조에는 크기보다 색과 weight를 먼저 씁니다. 최종 판매가와 할인율은 크기 차이가 크지 않지만 색과 배경으로 위계가 갈립니다.
- 가격의 색 역할이 고정되어 있습니다. 최종 판매가는 할인이 적용되면 빨강(Red), 적용되지 않으면 기본 텍스트 색(Gray/900)을 씁니다. 할인율은 항상 빨강(Red)입니다. 파랑(Blue)은 가격 강조에 쓰이지 않고 CTA 버튼과 링크 같은 행동 용도로만 쓰입니다.
- 그림자는 원칙적으로 쓰지 않습니다. 깊이는 대부분 얇은 구분선으로 표현합니다. `Toast`와 `Bottom Navigation`만 예외입니다.

## 2. Visual Style 분석

### Color

Semantic 토큰은 31개이며 모두 Primitive를 참조합니다. 아래는 화면의 시각 스타일을 결정하는 토큰입니다.

| 역할 | 값 | Primitive |
|---|---|---|
| `Text/Primary` | `#34373d` | Gray/900 |
| `Text/Description` | `#7b818e` | Gray/600 |
| `Text/On Color` | `#ffffff` | Static/0 |
| `Text/Accent` | `#106def` | Blue/500 |
| `Background/Background` | `#f4f6f6` | Gray/50 |
| `Background/Divider` | `#e3e5e8` | Gray/200 |
| `State/Primary` | `#106def` | Blue/500 |
| `State/Disabled` | `#cdd0d5` | Gray/300 |
| `Feedback/Error` | `#e23636` | Red/400 |
| `Feedback/Success` | `#1dc948` | Green/500 |
| `Feedback/Warning` | `#ffb33d` | Orange/400 |
| `Emphasis/Primary` | `#f2460d` | Point/500 |

- 파랑(Blue): CTA 버튼 배경과 링크 텍스트처럼 사용자 행동에만 쓰입니다. 가격 강조에는 쓰이지 않습니다. 화면에서 차지하는 면적은 작지만 행동 지점에는 반드시 등장합니다.
- 회색(Gray): 배경, 보조 텍스트, 구분선의 3단계로 나뉩니다. 서로 다른 회색을 섞어 쓰지 않습니다.
- 텍스트 위계: Primary, Description, On Color, Accent의 4단계입니다. Primary는 상품명과 핵심 정보에, Description은 보조 설명에 씁니다. On Color는 색 배경 위 텍스트에, Accent는 링크와 CTA에 해당합니다.
- 배경 위계: 페이지 배경은 연회색이고 컴포넌트는 대부분 흰색입니다. 흰 카드가 연회색 배경 위에 얹히는 구조입니다. 카드 표면 전용 토큰은 없고 흰색을 그대로 씁니다.
- 테두리 색: 구분선과 Line type 버튼 테두리 두 종류뿐이며 장식용 테두리는 없음
- 비활성 색: `State/Disabled` 하나로 통일
- 피드백 색: Error는 빨강, Success는 초록, Warning은 주황인 표준적인 3색 배정
- 강조색 빈도: 낮거나 중간 수준입니다. 한 화면에서 파랑은 CTA와 링크를 합쳐 2~4곳을 넘지 않습니다.
- 로켓 배지 색: 주황, 초록, 보라, 파랑 4색입니다. `Rocket` Primitive 패밀리의 변수 8개로 등록되어 있습니다. 배송 유형 4종마다 배경색과 텍스트색 변수를 하나씩 갖습니다. `Rocket Badge` 컴포넌트의 4개 variant가 모두 이 변수에 바인딩되어 있습니다. 배송 유형은 도메인에 특화된 개념이라 Semantic 레이어로 올리지 않았습니다. 원색이지만 배지 영역 안에만 쓰여 화면 전체 톤을 해치지 않습니다.

색은 다음과 같이 의미를 전달합니다.

| 색 | 의미 |
|---|---|
| 빨강(Red) | 할인율, 긴급, 할인이 적용된 최종 판매가 |
| 회색(Gray) | 중립 정보, 할인이 없는 최종 판매가 |
| 파랑(Blue) | 행동(CTA, 링크) |
| 로켓 배지 원색 | 배송 유형 식별 |

색은 장식으로 쓰이지 않고 모두 정보를 전달하는 용도로만 쓰입니다.

### Typography

글꼴은 Pretendard 하나입니다. 정의된 텍스트 스타일이 모두 Pretendard를 씁니다. 스타일은 6개 역할 카테고리에 총 29개가 있습니다.

| 카테고리 | 스타일 수 | 크기(px) |
|---|---|---|
| `display` | 0(예약) | — |
| `heading` | 7 | 30, 26, 22, 18, 16, 15 |
| `body` | 15 | 19, 16, 15, 14, 13, 12, 11 |
| `label` | 3 | 14, 13 |
| `navigation` | 3 | 16, 14 |
| `underline` | 1 | 13 |

- Weight: heading은 대부분 Bold입니다. body는 Regular, Medium, Bold 세 가지를 씁니다.
- Line height: 150%가 기본입니다. `body/small`, `body/compact`, `label/small`, `navigation/small` 4개만 140%를 씁니다.
- Letter spacing: 모두 0입니다. `body/large-bold`만 -0.5px을 씁니다. 가장 큰 금액 텍스트에만 자간을 좁혀 밀도감을 준 예외입니다.

커머스 정보의 텍스트 스타일은 아래와 같습니다.

| 요소 | 크기 | Weight | 스타일 |
|---|---|---|---|
| 최종 판매가 | 19px | Bold | `body/large-bold` |
| 할인율 | 14px | Bold | — |
| 상품명 | 15px | Medium | `body/compact-medium` |
| 평점 숫자 | 13px | Bold | — |
| 리뷰 수 | 13px | Regular | — |

- 가격: 최종 판매가가 본문 텍스트 중 가장 크고 진합니다. 할인율은 그보다 작고, 정가는 더 작은 회색에 취소선을 씁니다. 같은 숫자라도 확정 금액이 가장 크고 나머지는 보조로 축소됩니다.
- 평점과 리뷰 수: 같은 크기에서 weight만으로 위계 구분

### Spacing

컴포넌트의 padding과 gap은 아래와 같습니다.

| 컴포넌트 | 좌우 padding | 상하 padding | 내부 gap |
|---|---|---|---|
| Button(Large) | 20 | 11(예외) | 10(예외) |
| Button(Medium) | 8(예외) | 9(예외) | 10(예외) |
| Chip | 10(예외) | 6(예외) | 4(예외) |
| Action Bar | 16 | 16 | 0 |
| Item Card 내부 | 0 | 0 | 8 |
| Review Card 내부 | — | — | 16 |

반복되는 관계는 세 가지입니다.

| 관계 | 값 |
|---|---|
| 화면 좌우 마진 | 16px |
| 카드류 내부 요소 간 gap | 8px |
| 섹션 구분 | 8px 두꺼운 구분선과 16px 여백의 조합 |

- 화면 좌우 마진은 Grid Foundation의 마진과 일치합니다.
- 일관되게 지켜지는 것은 화면 마진과 카드 내부 gap입니다.
- Button과 Chip만 4의 배수를 벗어난 padding을 반복해서 씁니다. 이 값들은 Spacing 규칙이 허용하는 2px 단위 예외에 해당합니다.

### Shape

Radius는 공식 토큰 5단계입니다. 컴포넌트 라이브러리 전체 1,346곳에 바인딩되어 있습니다.

| 토큰 | 값 | 해당 요소 |
|---|---|---|
| `none` | 0 | Card, Action Bar, Bottom Sheet 본체 |
| `small` | 4 | Button Small, Button XSmall, Rocket Badge |
| `medium` | 8 | Button Large, Button Medium |
| `large` | 16 | Dialog와 Bottom Sheet 헤더의 상단 두 모서리 |
| `full` | 999 | Chip, Icon Button |

- `full`은 모서리가 요소 크기에 맞춰 잘리면서 pill이나 원으로 렌더링됩니다.
- 인터랙션이 가능한 작은 요소일수록 더 둥급니다. 둥근 정도는 `full`, `medium`, `small`, `none` 순입니다.
- 테두리 두께는 모두 1px입니다.
- 구분선은 두 종류만 반복됩니다. 행을 구분하는 1px과 섹션을 구분하는 8px입니다.
- Input: 검색창은 pill에 가까운 둥근 형태로 관찰됩니다. 정확한 radius 값은 아직 정의되지 않았습니다.
- Bottom Sheet는 `Bottom Sheet / Informational`과 `Bottom Sheet / Interactive` 모두 같은 형태입니다. 헤더의 상단 두 모서리만 둥글고 본체와 하단 모서리는 각져 있습니다.

모달형 오버레이는 높이에 상한을 둡니다.

| 컴포넌트 | 높이 상한 |
|---|---|
| Dialog | `max-height: 70vh` |
| Bottom Sheet | `max-height: 80vh` |

높이를 고정 px가 아니라 뷰포트 상대 단위로 제한합니다.

### Elevation / Surface

| 항목 | 내용 |
|---|---|
| 정의된 이펙트 스타일 | `shadow` 1개. DROP_SHADOW, radius 10, 검정 5% |
| 예외 1 | `Toast`에 BACKGROUND_BLUR 3건 |
| 예외 2 | `Bottom Navigation`에 DROP_SHADOW 2건 |

- 그림자는 원칙적으로 쓰지 않습니다. 이펙트 스타일이 정의되어 있지만 대부분의 노드에는 바인딩되어 있지 않습니다.
- 예외인 두 컴포넌트는 모두 화면 위에 떠 있는 고정 오버레이입니다. 의도된 예외로 잠정 분류합니다.
- 표면 위계는 흰 카드와 연회색 배경의 2단계뿐입니다. 카드 위에 또 다른 카드가 얹히는 3단계 이상의 구조는 관찰되지 않습니다.
- 테두리와 구분선을 주로 사용합니다. 깊이감보다 선으로 나누는 평면적 스타일이 기본입니다.

### Iconography

| 항목 | 값 |
|---|---|
| 기본 크기 | 16×16 |
| 터치 영역 | 32×32 |
| Chevron 선 두께 | 1.5px |
| Chevron 그래픽 크기 | 5×10 |

- 크기: Chevron Right를 비롯한 대부분의 아이콘이 기본 크기입니다. Rating 아이콘도 같은 크기로 관찰됩니다. 상품문의 리스트의 chevron처럼 터치 영역이 더 큰 경우에도 내부 그래픽은 기본 크기를 유지합니다.
- 선: 작은 화살표를 가는 선으로 그린 thin outline 스타일
- 텍스트와의 관계: 아이콘의 시각적 무게는 텍스트보다 작거나 비슷합니다. 아이콘이 텍스트를 압도하지 않습니다. 로켓 배지처럼 아이콘과 텍스트가 한 세트인 경우가 많습니다. 단독 아이콘보다 라벨을 동반하는 구성이 기본형입니다.
- Filled와 Outline: 로켓 배지 아이콘은 원색으로 채운 filled입니다. Chevron과 UI 컨트롤 아이콘은 선만 있는 outline을 씁니다. 정보성 아이콘은 filled, 내비게이션과 컨트롤 아이콘은 outline으로 갈리는 경향이 있습니다.
- `Icon Button`: 아이콘 전용 버튼 컴포넌트가 정식으로 존재합니다. 형태는 pill입니다. 실사용은 리뷰의 "도움이 돼요" 하나뿐입니다.
- `Icon / Checkbox`와 `Icon / Radio`: 둘 다 원색으로 채운 아이콘이라 filled 경향을 따릅니다. 다만 두 컴포넌트 모두 "선택 안 됨"을 표현하는 variant가 없습니다. 시각 언어로는 filled 원칙에 맞지만 체크와 언체크를 전환하는 인터랙티브 컴포넌트는 아닙니다. Icon / Checkbox는 `Item Card / Cart`, `Cart / Selection Toolbar`, 장바구니 화면에서 실사용 중입니다.

Icon Button의 variant 구성은 아래와 같습니다.

| Property | 값 |
|---|---|
| Type | Secondary, Line type gray |
| Size | Medium, Small |
| Status | Default, Pressed |

## 3. Information Hierarchy 분석

| 요소 | 크기 | Weight | 색 | 위치 | 배경 |
|---|---|---|---|---|---|
| 최종 판매가 | 19px(가장 큼) | Bold | 할인 적용 시 빨강(Red), 미적용 시 Gray/900 | 할인율 배지 바로 옆 | 없음 |
| 할인율 | 14px | Bold | 흰색 | 판매가 왼쪽, 독립 배지 | 빨강(Red) |
| 정가(취소선) | 작음 | Regular | 회색, 취소선 | 판매가 위 | 없음 |
| 상품명 | 15px | Medium | 검정 | 가격 위 | 없음 |
| 배송 정보(로켓) | 13px대 | Regular, Bold | 로켓 배지는 원색, 설명 텍스트는 회색 | 가격 아래 | 배지만 원색 |
| 평점 | 13px | 숫자는 Bold, 부가 정보는 Regular | 검정, 주황 별 아이콘 | 배송 정보 아래 | 없음 |
| 리뷰 수 | 13px | Regular | 회색 | 평점 옆, 구분선으로 분리 | 없음 |
| 상태(품절 등) | Info Label로 처리 | — | — | — | — |
| CTA | 16px대 | Bold | 흰색 텍스트 | 화면 폭을 꽉 채움 | 파랑(Blue), 면 전체 |
| 보조 설명(옵션 등) | 13px | Regular | 회색 | 본문 하단 | 없음 |
| 메타데이터(날짜 등) | 13~14px | Regular | 회색 | 최하단 | 없음 |

이 디자인은 배경색을 가진 요소가 가장 강한 강조라는 규칙을 씁니다. 화면 전체에서 배경색이 채워지는 곳은 할인율 배지와 CTA 버튼 두 곳뿐입니다. 할인율은 배경색을 쓰는 유일한 정보입니다. 그 외의 위계는 배경 없이 크기, weight, 텍스트 색으로 처리합니다.

강조 수단의 강도는 배경색 채움, 텍스트 색, 크기, weight 순으로 약해집니다. 가장 강한 배경색 채움은 중요한 요소에만 아껴 씁니다.

## 4. Component의 시각적 문법

- Button: radius는 크기 티어별로 묶입니다. Large와 Medium이 한 티어, Small과 XSmall이 한 티어입니다. 좌우 padding은 Large와 Medium의 차이가 큽니다. 상하 padding은 둘 다 4의 배수를 벗어난 예외값입니다. 버튼 높이는 4의 배수 규칙보다 시각적 균형을 우선한다는 것을 보여주는 반복 패턴입니다.
- Chip: 완전한 pill 형태입니다. 기본 상태는 얇은 1px 테두리이고, 선택 상태는 채움으로 전환됩니다. Button과 달리 테두리 기반이 기본 상태입니다.
- Card: Item Card와 Review Card 모두 이미지, 텍스트 정보, 구분 요소, 메타데이터 순서가 반복됩니다. 내부 gap은 공통적으로 8~16px입니다. 카드 자체에는 테두리와 그림자가 없습니다. 흰 카드와 연회색 페이지 배경의 대비만으로 경계를 표현합니다.
- 탭형 선택 UI: `Tab Group`과 `Category Tab`, Chip은 겉보기에 비슷한 가로 선택 UI지만 역할이 다릅니다. Tab Group은 같은 데이터를 관점별로 재구성합니다. 장바구니의 일반구매, 자주산상품, 찜한상품이 그 예입니다. Category Tab과 Chip은 서로 다른 카테고리나 옵션을 나열해 선택하게 합니다.

여러 컴포넌트에 공통되는 문법은 세 가지입니다.

1. 색이 있는 요소는 항상 둥글고, 정보 텍스트는 항상 각져 있습니다.
2. 상태 전환은 배경색보다 텍스트와 테두리의 색 변화로 표현하는 경우가 많습니다. Button의 Pressed는 톤다운이고, Line type은 테두리만 채웁니다.
3. 강조 색상인 파랑과 빨강은 큰 면적을 차지하지 않습니다. 배지와 버튼 같은 작은 단위에만 쓰입니다.

모달형 오버레이인 Dialog와 Bottom Sheet는 높이와 스크롤을 같은 방식으로 처리합니다.

- 둘 다 전체 높이를 고정 px가 아니라 뷰포트 상대 단위로 제한합니다.
- 스크롤 인디케이터는 구분선과 스크롤바로 구성되며 `Show Scroll` Boolean으로 제어합니다.
- 인디케이터는 길이를 예측할 수 없는 자유 텍스트 콘텐츠에만 붙습니다. Dialog와 Bottom Sheet Informational이 해당합니다.
- 리스트와 캐러셀처럼 형태 자체가 스크롤을 암시하는 콘텐츠에는 붙지 않습니다. Bottom Sheet Interactive가 여기에 속합니다.

## 5. Commerce UI 특유의 스타일

| 정보 | 표현 방식 |
|---|---|
| 가격(최종) | 19px Bold. 할인 적용 시 빨강(Red), 미적용 시 Gray/900 |
| 할인율 | 14px Bold 흰 글씨와 빨강(Red) 배경의 pill |
| 할인 전 가격 | 작은 회색 텍스트와 취소선 |
| 배송 정보 | 회색 텍스트. 로켓 관련이면 원색 배지를 동반 |
| 로켓 관련 | `Rocket Badge` 컴포넌트. 주황, 초록, 보라, 파랑 4색이며 아이콘과 텍스트가 한 세트. radius는 `small` |
| 평점 | 주황 별 아이콘, 검정 Bold 숫자, 회색 부가 정보 |
| 리뷰 수 | 회색 Regular. 평점과 구분선으로 구분하되 같은 행에 배치 |
| 적립 혜택 | 라벨과 내용으로 구성된 Info Row 패턴. 컴포넌트가 있으나 일부 화면에서는 컴포넌트 없이 직접 구현되어 있음 |
| 품절 | Info Label 컴포넌트의 SoldOut 라벨로 정의되어 있음 |
| 프로모션 | 전용 색상이 정의되어 있지 않음 |
| CTA | 파랑(Blue) 풀블리드 버튼. 항상 화면 폭을 꽉 채움 |
| 상품 옵션 | 수량을 조절하는 Quantity Stepper와 안내 문구("2개 사면 2,300원 절약")의 조합 |

정보가 많을 때 복잡도를 낮추는 방식은 네 가지입니다.

1. 향 만족도 같은 리뷰 상세 지표는 막대바와 퍼센트로 축약합니다.
2. 긴 리뷰 본문은 처음 몇 줄만 보여줍니다. Review Card의 본문이 고정 영역이기 때문입니다.
3. 추천 상품군은 가로 스크롤 캐러셀로 배치해 세로 스크롤 길이를 줄입니다.
4. 상품가, 할인, 배송비, 예상금액 같은 결제 항목은 얇은 구분선으로만 나눈 단순 리스트로 나열합니다. 마지막 합계만 Bold로 강조합니다.

## 6. Design Language 요약

### Visual Character

연회색 배경 위에 흰 카드가 얹히는 평면적 구조입니다. 그림자와 깊이 표현은 원칙적으로 없고 얇은 선만으로 영역을 나눕니다. Toast와 Bottom Navigation만 예외입니다.

색은 검정과 회색의 무채색이 기본입니다. 강조색은 행동을 뜻하는 파랑과 할인·최종가를 뜻하는 빨강 두 가지뿐입니다. 두 색은 배지, 버튼, 가격 숫자 같은 좁은 영역에만 집중적으로 쓰입니다.

### Color Language

회색 3단계가 기반입니다. 배경, 구분선, 보조 텍스트에 각각 쓰입니다.

파랑(Blue)은 CTA와 링크 같은 행동에만 배정되고 가격 강조에는 쓰이지 않습니다. 빨강(Red)은 할인율, 긴급성, 그리고 할인이 적용된 최종 판매가에 배정됩니다. 할인이 없는 최종 판매가는 기본 텍스트 색(Gray/900)을 씁니다.

배경색이 채워지는 요소는 화면 전체에서 CTA 버튼과 할인율 배지 두 종류뿐입니다. 나머지 위계는 텍스트 색만으로 처리합니다. 로켓 배송 배지 4색은 `Rocket` Primitive 패밀리로 토큰화되어 있고, 좁은 배지 영역 안에만 쓰입니다.

### Typography Language

Pretendard 단일 패밀리입니다. 6개 역할 카테고리에 총 29개 스타일이 있습니다. 대부분 line height가 150%로 고정되어 있습니다.

가격과 평점처럼 커머스에서 중요한 숫자는 크기보다 Bold weight로 먼저 강조합니다. 그중 최종 판매가만 body 스케일에서 가장 큰 크기를 씁니다. 상품명은 `body/compact-medium` 스타일에 바인딩되어 있습니다.

### Spacing Language

화면 좌우 마진 16px과 카드 내부 요소 gap 8px이 가장 강하게 반복됩니다. 섹션 사이는 8px 두꺼운 구분선과 16px 여백의 조합입니다.

4의 배수 원칙은 레이아웃 수준에서 잘 지켜집니다. 버튼과 칩처럼 작은 인터랙션 요소의 세로 padding에서만 2px 단위 예외가 허용됩니다. 이는 Spacing 규칙이 명시한 예외와 일치합니다.

### Shape Language

Radius는 공식 토큰 5단계를 씁니다.

| 요소 | 토큰 |
|---|---|
| Button Large, Button Medium | `medium` |
| Button Small, Button XSmall | `small` |
| Chip, Icon Button | `full` |
| Card, Action Bar | `none` |
| Dialog와 Bottom Sheet의 헤더 상단 모서리 | `large` |

작고 눌리는 요소일수록 둥글게 처리합니다. large는 이 축과 별개로 모달형 오버레이의 헤더 상단 모서리에만 씁니다.

테두리는 항상 1px입니다. 그림자는 원칙적으로 쓰지 않고 테두리와 구분선이 깊이 표현을 전담합니다. Toast와 Bottom Navigation만 예외입니다.

### Icon Language

16×16 크기를 기준으로 하고 가는 outline 위주입니다. 내비게이션과 컨트롤 아이콘은 outline이고, 배송 배지 같은 정보성 아이콘은 원색 filled입니다. 역할에 따라 스타일이 갈립니다. 아이콘 단독보다 텍스트와 짝을 이루는 구성이 기본형입니다.

전용 `Icon Button` 컴포넌트가 정식으로 존재합니다. 실사용은 리뷰의 "도움이 돼요" 하나뿐입니다.

`Icon / Checkbox`와 `Icon / Radio`도 filled 원칙을 따릅니다. 다만 둘 다 "선택 안 됨" variant가 없습니다. 시각 언어로만 완성되어 있고 아직 토글 컴포넌트는 아닙니다.

### Information Hierarchy

강조 강도는 배경색 채움, 텍스트 색, 크기, weight 순으로 약해집니다. 배경색을 쓰는 요소는 CTA와 할인율 배지뿐입니다. 이 디자인은 강조 수단을 아껴 쓰고, 눌러야 하는 지점과 중요한 숫자에만 최상위 시각 강조를 배정합니다.

### Interaction Language

Button은 Pressed 상태에서 색을 톤다운합니다. 배경 자체를 바꾸지 않고 어둡게 만듭니다. Line type은 테두리만 채워진 상태로 존재합니다. Chip은 테두리에서 채움으로 바뀌는 방식으로 선택 상태를 표현합니다. 선택 상태의 색상은 아직 정의되지 않았습니다.

상태 전환은 대체로 색의 진하기로 표현되고 형태는 거의 바뀌지 않습니다.

### Commerce Language

최종 판매가는 할인이 적용되면 빨강, 적용되지 않으면 기본 텍스트 색(Gray/900)을 씁니다. 할인율에는 빨강 배경이 들어갑니다. 배송 배지는 원색 아이콘과 텍스트의 세트입니다. 리뷰 상세 지표는 막대바와 퍼센트로 축약합니다.

리뷰, 추천 상품, 결제 내역처럼 정보 밀도가 높아지는 지점은 두 가지 방식으로 시각적 복잡도를 낮춥니다. 얇은 구분선으로 나눈 단순 리스트와 가로 스크롤 캐러셀입니다.

### Core Design Principles

1. 강조는 배경색 채움을 최상위 수단으로 아껴 씁니다. 화면 전체에서 배경이 채워지는 요소는 CTA와 할인율 배지뿐입니다.
2. 색의 의미가 고정되어 있습니다. 파랑(Blue)은 CTA와 링크 같은 행동을 뜻합니다. 빨강(Red)은 할인율, 긴급, 할인이 적용된 최종 판매가를 뜻합니다. 할인이 없는 최종 판매가는 기본 텍스트 색(Gray/900)이며, 파랑은 가격 강조에 쓰이지 않습니다.
3. 인터랙션이 가능한 작은 요소일수록 더 둥급니다. Radius 토큰은 `full`, `medium`, `small`, `none` 순으로 둥급니다.
4. 깊이는 원칙적으로 그림자가 아니라 선으로 표현합니다. 정의된 shadow 이펙트 스타일은 대부분 쓰이지 않습니다. 고정 오버레이 컴포넌트인 `Toast`와 `Bottom Navigation`만 예외입니다.
5. 커머스 숫자는 크기보다 weight로 위계를 나눕니다. 평점 숫자와 리뷰 수는 같은 크기에서 Bold와 Regular로만 구분됩니다.
6. 여백은 화면 마진 16px과 카드 내부 8px 두 값이 대부분을 지배합니다. 버튼과 칩류만 예외를 허용합니다. 이는 4배수 Spacing 규칙과 일치합니다.
7. 정보 밀도가 높아지면 구분선으로 나눈 리스트나 가로 캐러셀로 낮춥니다. 새 레이아웃 패턴을 만들지 않습니다.
8. 아이콘은 역할에 따라 outline과 filled로 나뉩니다. 컨트롤 아이콘은 outline이고 정보성 배지 아이콘은 filled입니다.
9. 모달형 오버레이의 높이는 뷰포트 상대 단위로 제한합니다. 스크롤 인디케이터는 콘텐츠 형태에 따라 선택적으로 붙습니다. 자유 텍스트 콘텐츠에만 구분선과 스크롤바가 들어갑니다.
10. 탭형 선택 UI는 역할에 따라 컴포넌트가 분리됩니다. `Tab Group`은 같은 데이터를 관점별로 재구성합니다. `Category Tab`과 Chip은 서로 다른 대상을 나열해 선택하게 합니다.

## 7. 최종 정리

### 1. 현재 디자인에서 가장 강하게 드러나는 스타일 5가지

1. 평면과 테두리 기반 구조입니다. 그림자는 원칙적으로 쓰지 않고 구분선이 깊이 표현을 전담합니다. Toast와 Bottom Navigation만 예외입니다.
2. 강조색 2종의 역할이 엄격히 분리되어 있습니다. 파랑은 행동, 빨강은 할인율·긴급·할인이 적용된 최종 판매가를 나타냅니다.
3. 배경색 채움을 가장 강한 강조 수단으로 아껴 씁니다. CTA와 할인율 배지 외에는 쓰지 않습니다.
4. 공식 5단계 Radius 토큰에 따라 형태 규칙이 일관됩니다. 요소가 작고 인터랙션 성격이 강할수록 둥급니다.
5. 16px 화면 마진과 8px 카드 내부 gap이 여백을 지배합니다.

### 2. 아직 스타일이 명확하게 정의되지 않은 부분

1. Input(검색창)의 radius 값: 아직 정의되지 않음
2. Chip의 Selected 상태 색상값: 아직 정의되지 않음

### 3. 새 컴포넌트 제작 규칙

- 배경색 채움은 CTA나 긴급 신호처럼 중요한 요소에만 씁니다. 장식으로 배경색을 쓰지 않습니다.
- 색과 의미의 대응을 그대로 따릅니다. 파랑은 CTA와 링크 같은 행동에만 씁니다. 빨강은 할인율, 위험 신호, 할인이 적용된 최종가 강조에 해당합니다. 파랑을 가격 강조에 쓰지 않습니다.
- Radius는 공식 5단계 토큰 중 요소의 크기와 인터랙션 성격에 맞는 값을 씁니다. 작고 누르는 요소일수록 둥글게 합니다.
- 그림자를 쓰지 않고 구분선과 여백으로 경계를 표현하는 것이 기본입니다. 고정 오버레이류만 예외를 검토할 수 있습니다.
- 화면 마진 16px과 카드 내부 gap 8px을 기본값으로 삼습니다.
- Dialog나 Bottom Sheet 같은 모달형 오버레이를 새로 만들 때는 높이를 고정 px가 아니라 뷰포트 상대 단위로 제한합니다. 스크롤 인디케이터는 자유 텍스트 콘텐츠에만 붙이고 리스트와 캐러셀 형태의 콘텐츠에는 붙이지 않습니다.
- 가로로 여러 옵션을 나열하는 선택 UI를 새로 만들 때는 역할을 먼저 구분합니다. 같은 데이터를 관점별로 재구성하면 Tab Group류를, 서로 다른 대상을 나열해 고르게 하면 Category Tab이나 Chip류를 재사용합니다.

### 4. 아직 정하지 않을 부분

- Input의 radius 값: 합의된 값이 없으므로 임의로 정하지 않음
- Chip의 Selected 색상: 정의되지 않은 상태이므로 다음 컴포넌트 설계 때 확인한 뒤 진행
